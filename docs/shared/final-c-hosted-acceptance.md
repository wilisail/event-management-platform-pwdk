# Final C — hosted F2 integration and acceptance data

Updated 13 November 2026. Project responsibilities remain Wili (F2) and Rizky (F1).

Preparation is in progress. C verifies the normal hosted F2 endpoints using controlled purchase inputs, then leaves two clearly marked purchases for D's manual acceptance. It does not implement F1 checkout or claim that a real bank transfer occurred.

The maintenance utility is separate from the normal application routes. It requires the existing protected Preview, backend credentials, an explicit fixture manifest and a time-limited preparation window. Private credentials, platform access and account identifiers are supplied outside the repository. The utility validates the selected project/account roles, uses the existing reward service for reservations, and creates only its named fixture cohort.

The automated cohort exercises protected proof bytes, role/ownership checks, persisted approval/rejection and reward changes, queued notifications, duplicate prevention, attendance/reviews and deadline execution through the actual deployed endpoints. Temporary notifications are held outside external transport and removed with their test records. Actual inbox receipt remains a D check.

The manual cohort uses the existing Organizer and two Customer accounts, a separate clearly labelled event, and private PNG proofs marked **TIDAK ADA UANG DITRANSFER**. One purchase reserves 5,000 points; the other reserves the referred Customer's coupon. No account password, profile or original accepted event is replaced. Exact references, links, deadlines and expected balances will be recorded after hosted verification completes.

The documentation uses project ownership and standard engineering test terms. Automated evidence retains its actual scope and results; it is not relabelled as manual acceptance.
